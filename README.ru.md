Персональное портфолио, в котором само портфолио является частью
представляемой работы.

Сайт объединяет шесть разных проектов: brutalist fashion concept,
японский ресторан, юридическую фирму, CRM dashboard, landing page
AI-курса и Telegram-бота.

Задача была не просто показать их в одном месте, а позволить разным
визуальным идентичностям существовать внутри единого интерфейса, не
превращая все проекты в один типовой шаблон.

## Визуальная система

На всей странице используется один непрерывный background layer.

По мере движения пользователя этот слой переходит между визуальными
идентичностями проектов. Тот же механизм отвечает за светлое начало
страницы, цвета отдельных проектов, переходы между секциями и
инвертированный финальный экран.

Секции не имеют собственных независимых background. Вместо этого они
задают состояние, которое требуется странице, а общий controller
интерполирует текущие значения фона и foreground.

## Проекты как часть интерфейса

Секция проектов построена как интерактивная карусель, а не обычная сетка
portfolio cards.

Каждый проект переносит собственную визуальную идентичность в окружающий
интерфейс. Карусель поддерживает управление с клавиатуры и свайпы, а
неактивные карточки исключаются из tab order.

Обратная сторона карточки использует непрозрачную поверхность,
производную от цвета самого проекта. Благодаря этому переход остается
стабильным даже при движении между сильно различающимися фоновыми
состояниями страницы.

![Проекты](docs/preview/02-projects.png)

## Фон, который управляет контрастом

Цвет текста не привязан к фиксированной черно-белой теме.

Интерфейс вычисляет относительную luminance текущего фона и на ее основе
определяет, каким должен быть основной текст: светлым или темным.
Вторичный и третичный текст затем смешивается с активным фоном вместо
использования двух фиксированных оттенков серого.

Это позволяет одной типографической системе оставаться читаемой, пока
страница проходит через белый, почти черный, красный, navy, желтый и
синий этапы.

В результате интерфейс может менять визуальный характер без создания
отдельной темы для каждого проекта.

## Когда визуальная идея превращается в структуру

Секция «Мой подход» использует canvas-поле из 936 точек.

В начале они образуют рассеянную композицию, а по мере продвижения
секции через viewport постепенно собираются в сетку из двенадцати
колонок.

Анимация напрямую связана со смыслом секции: абстрактное поле
превращается в визуальную структуру.

Canvas использует один `requestAnimationFrame` loop, а курсор
одновременно управляет локальным lens-эффектом и движущимся светом.

![Подход](docs/preview/03-approach.png)

## Анимация без разрушения контента

Motion используется для раскрытия структуры, а не просто для появления
элементов.

Три абзаца о подходе к работе появляются слово за словом. После точки
устанавливается более длинная пауза, чем после запятой, благодаря чему
текст получает естественный ритм чтения.

Полный текст находится в DOM с самого начала. Во время анимации меняется
только opacity, поэтому layout не перестраивается в процессе, а
assistive technologies сразу получают весь текст.

Проект также учитывает `prefers-reduced-motion`. Сложные секции
переходят в более простой layout вместо того, чтобы превращаться в
пустую или сломанную композицию при отключении анимаций.

## Pipeline изображений проектов

Скриншоты проектов подготавливаются до того, как попадают в браузер.

Build script выполняет несколько операций:

- удаляет подписи, которые уже отображаются самим интерфейсом
- приводит изображения к единому формату 16:10
- генерирует AVIF и WebP
- создает несколько размеров для responsive loading
- сохраняет размеры в markup, предотвращая layout shift

В результате набор исходных renders размером около 8.66 MB сокращается
примерно до 0.60 MB готовых assets.

Браузер может выбрать подходящий размер через `srcset`, вместо загрузки
самой большой версии для каждой карточки.

## Типографика

Для трех разных задач используются три гарнитуры.

Manrope отвечает за основную визуальную структуру и display-типографику.

Inter используется для интерфейсных элементов и дополнительного текста.

Playfair Display появляется выборочно внутри заголовков, создавая
контраст между технической структурой интерфейса и более человеческими
частями текста.

Выделенные слова являются частью translation data, поэтому их положение
может меняться вместе с языком, а не быть жестко задано в
JSX-компоненте.

## Локализация

Сайт поддерживает русский и английский языки через типизированную
систему словарей.

Язык определяется в следующем порядке:

1. ранее сохраненный выбор
2. язык браузера
3. соответствующий доступный язык

Выбранный язык сохраняется в `localStorage` и управляет не только
интерфейсом, но и metadata документа.

При переключении обновляются:

- текст интерфейса
- `<html lang>`
- title документа
- meta description

Оба словаря реализуют одну типизированную структуру, поэтому отсутствие
перевода становится compile-time проблемой, а не незаметной пустой
строкой в одной из версий.

## Взаимодействие и доступность

Карусель поддерживает управление с клавиатуры и touch gestures.

Неактивные карточки получают `inert` и не попадают в tab order, пока
другая карточка находится в активном состоянии.

Focus indicators используют текущий цвет foreground вместо фиксированного
цвета, который мог бы исчезнуть на одном из фоновых состояний страницы.

Контент также остается доступным без JavaScript. Reveal-анимации
начинают скрывать элементы только после инициализации приложения,
поэтому без scripting документ не превращается в набор пустых секций.

## Структура frontend

Приложение разделено на секции страницы, общие компоненты, content
dictionaries и stage system, отвечающую за глобальное визуальное
состояние.

```text
src/
├── components/
├── content/
├── lib/
├── sections/
├── stage/
├── App.tsx
├── i18n.tsx
├── index.css
└── main.tsx
```

Основная композиция страницы собирается через общий `StageProvider`, а
i18n provider предоставляет активный язык и соответствующий словарь
контента.

Так композиция страницы остается отделена от механизмов, отвечающих за
глобальный stage, локализацию, анимации и данные.

## Техническая основа

В проекте используются:

- React 19 для интерфейса
- TypeScript для типизации структуры приложения
- Vite как build system
- Tailwind CSS 4 как основа стилизации
- Motion для интерфейсных анимаций
- Sharp для image pipeline проектов
- self-hosted Manrope, Inter и Playfair Display

UI kit, component library или page builder в проекте нет.

Визуальная система собрана специально под этот проект и включает stage
transitions, project cards, canvas-композицию, типографику и responsive
behavior.

## Деплой

Проект размещен на GitHub Pages через GitHub Actions из ветки `main`.

Production build сначала выполняет TypeScript checks, после чего Vite
создает финальный bundle. Изображения проектов можно повторно обработать
через отдельный image-processing script при изменении исходных renders.

## Границы проекта

Этот репозиторий и есть само портфолио.

Проекты внутри него представлены как отдельные работы, а текущий
application показывает, как разные визуальные системы можно объединить в
один цельный интерфейс.

Задача не в том, чтобы скрыть различия между проектами, а в том, чтобы
построить достаточно гибкую оболочку, которая позволяет этим различиям
сохраниться.

## Итог

Портфолио построено так, чтобы сам интерфейс демонстрировал те же
качества, которые он показывает в отдельных проектах.

По мере движения по странице меняются фон, контраст, типографика,
движение, изображения и модель взаимодействия.

В результате это не нейтральный контейнер для скриншотов, а отдельный
frontend-проект в портфолио со своей визуальной системой, interaction
design, performance-решениями, адаптивностью, локализацией и
доступностью.
